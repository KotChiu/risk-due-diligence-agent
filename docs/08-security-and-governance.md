# 08 · 隐私、信贷治理与访问控制

## 数据管理

- GitHub 仓库**不提交真实客户原始 QA、身份信息、账号、授信明细或生产密钥**。`examples/` 全是虚构样本。
- 原始材料存储在授权业务环境，落库前去标识化、字段最小化、权限隔离；原文 span 可用有权限的 source ID 追溯。
- 测试日志、模型请求、Prompt 缓存也可能含客户信息，需要脱敏、限权、留存期与审计策略。
- Private 仓库仍不能替代数据管理与最小权限原则。

## 权限矩阵

| 身份 | Public State | Hidden Facts | Evaluation Labels | Reward Audit |
|---|---|---|---|---|
| Risk Agent | 是 | 否 | 否 | 否 |
| Simulator Generator | 只需当前问题 | 仅已许可 DisclosurePlan | 否 | 否 |
| Disclosure Gate | 必要部分 | 是（仅符合准入标准） | 否 | 写入局部 audit |
| State Manager | 是 | 否（只处理公开 evidence refs） | 否 | 事件记录 |
| Verifier | 是 | 是 | 是 | 是 |
| Trainer | 可见轨迹 | 通过隔离的 reward 服务间接使用 | 不直接拼入 policy context | 可以读取奖励 |

## 研究与真实授信的边界

- 项目定位是**辅助风险发现**，不作自动授信决定，真实决策需另行验证与人类审批。
- 不可将受法律保护的人口特征、歧视性代理变量或不相关私人信息作为负向风险推断依据。
- 业务上线需模型风险审查、样本代表性和偏差检查、人工申诉/纠错机制、日志可追溯及适用法律合规审查。
- 客户解释是未经核实的信息。风险更新必须区别推断、陈述与独立证据，避免误伤客户。

## 模型安全

- 将客户回答、合同文本等视为不可信**数据**，不得执行其中的“忽略前述指令”“泄露隐藏信息”等文本指令。
- 结构化 Parser、披露权限规则和 Grounding Verifier 需具备安全回退。
- 限制 API 反复探查隐藏事实；生产环境应做 Rate Limit、预算限制、访问与操作审计。
- 对第三方模型服务需核对数据驻留、保留政策、用途授权和合同要求。
