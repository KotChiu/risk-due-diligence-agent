# 00 · 决策记录与边界

## 已确认（Confirmed）

| ID | 决策 | 背景 |
|---|---|---|
| D-001 | 目标是风险发现与尽调（A） | 改善风险假设与信息收集，不直接决定授信金额 |
| D-002 | 第一版使用模拟客户 Agent | 先构建可重复的多轮环境，再扩展真实交互 |
| D-003 | 来源包含历史 QA、尽调摘要、结构化结论 | 客户记录覆盖不完整 |
| D-004 | 采用混合证据模式 | 区分客户陈述、核验事实、专家推断 |
| D-005 | 采用语义相关事实披露 | 宽泛问题可得到自然解释，精确数据需进一步追问 |
| D-006 | 三步风险循环 | 风险识别 → 生成问题 → 解释理解与风险更新 |
| D-007 | 多轮可新增、缓解或保持风险 | 解释并不自动解除风险 |

## V1 工程暂定（Proposed Defaults）

- 单轮一个 `ASK` 问题；动作空间先只支持 `ASK`、`STOP`。
- `max_turns=5`，允许提前停止；不是固定最佳轮数。
- 尽调摘要中的 S2 客户陈述可进入 Simulator；S3 独立核验信息通过未来证据工具扩展；S4 结论只供 Verifier；S5 合成拓展暂不作真实事实。
- 风险状态使用 `SUSPECTED`、`EXPLAINED_UNVERIFIED`、`SUPPORTED`、`MITIGATED`、`UNRESOLVED`、`REJECTED`。
- 一个 LLM 可以分别通过不同任务 Prompt 实现 Risk Analyzer、Question Planner、Risk Updater；不要求三模型独立部署。
- 奖励公式、风险严重度、信息增益权重以及检索阈值全部需要离线校准。

## 非目标（Out of Scope）

1. 自动批准/拒绝贷款或计算最终授信额度。
2. 将模拟客户生成的扩写内容视为真实业务事实。
3. 以“负面标签越多越好”作为优化目标。
4. 用未来逾期结果补写过去的客户解释。
5. 未经治理将原始敏感客户数据公开到仓库。

## 开放问题（Open）

- 真实样本的 Gold/Silver/Bronze 占比及风险标签可审计比例。
- 业务风险分类体系、严重度标注标准、可接受的 STOP 条件。
- 面向摘要中的事实归属不明段落的专家复核流程。
- 证据核验工具（合同/账款/流水）是否在 V2 增加 `VERIFY` 动作。
- RL 使用的离线/在线算法、训练算力、评估样本规模。

所有开放问题在代码和表中都应以配置或版本化元数据表达，而不是硬编码为业务真理。
